# ۰۰۰۳: جداسازی داده‌ی شرکت‌ها

**وضعیت:** تصمیم گرفته شده، هنوز پیاده نشده

## تصمیم
- یک دیتابیس و یک schema مشترک؛ هر رکورد خصوصی به `organization` وابسته است.
- منابع خصوصی زیر `/api/v1/organizations/{org_id}/...` هستند و یک dependency واحد عضویت کاربر را
  بررسی می‌کند. غیرعضو **404** می‌گیرد، نه 403.
- مجوزها صریح‌اند و کد فقط مجوز را چک می‌کند، نه نام نقش.
- خواندن عمومی از مسیرهای جدا با Schemaهای allowlist انجام می‌شود.
- ایندکس جست‌وجو فقط داده‌ی عمومی دارد.
- تست قراردادی خودکار برای دسترسی بین‌شرکتی. Row-Level Security بعداً به‌عنوان لایه‌ی اضافه بررسی می‌شود.

## دلیل
جلوگیری از IDOR باید ساختاری باشد، نه وابسته به دقت برنامه‌نویس در هر endpoint.
